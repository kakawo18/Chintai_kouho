# 物件メモ

気になる物件を**地図にメモして見比べる**ための Web アプリです。**ひとりで使えます。**
誰かと一緒に探すことになったら、URL を送るだけで共有に切り替えられます。

住所の羅列では位置関係が掴めません。地図に落とすことで「どのエリアに絞るか」を
判断できるようにするのが狙いです。内見の現地でスマホから開いて使えます。

- 地図に物件をピンで並べ、**ピンをタップすると家賃・間取り・駅からの距離などの条件が出ます**
- 物件ページの **URL を貼るだけで項目が自動で埋まります**（任意のセットアップが必要）
- 住所に番地が無いページでも、**位置を「このあたり」の範囲として持てます**。あとからいつでも確定できます
- 家賃の上限、間取り、★、検討ステータスで絞り込むと、一覧と地図が同時に絞られます
- 「気になる／内見予定／内見済／候補外」で状態を管理でき、ピンの色に反映されます（[色の決まり](#色の決まり)）
- ホーム画面に追加すればアプリのように起動でき、一度見た地図は圏外でも表示されます

### 誰かと共有する場合

- URL を送るだけで参加でき、**追加・編集がお互いの画面にすぐ反映されます**
- **★評価は人ごと**に記録するので、評価が割れている物件がひと目で分かります
- 物件ごとに一言コメントを残せます
- 誰が追加し、誰がいつ更新したかがカードに出ます

共有はいつ始めても構いません。ひとりで貯めたリストをそのまま相手に見せられます。

ビルド工程はありません。HTML と JavaScript をそのまま置くだけで動きます。

## セットアップ

データの保存先として Firebase プロジェクトが1つ必要です。以下は**あなたの作業**です（10分程度）。

### 1. Firebase プロジェクトを作る

[Firebase コンソール](https://console.firebase.google.com) →「プロジェクトを追加」

- Google アナリティクスは**オフ**で構いません
- **「Blaze プランにアップグレード」は承諾しないでください。** 無料の Spark のままなら、万一いたずらされても料金は発生せず、上限に当たって止まるだけです

### 2. Firestore を作る

左パネルの **Databases & Storage > Firestore** →「データベースを作成」

- エディション：**Standard**
- ロケーション：**`asia-northeast1`（東京）** ※後から変更できません
- ルールのモード：**本番環境モード**（次の手順で自前のルールに置き換えます）

### 3. 匿名認証を有効にする

**Security > Authentication** →「始める」→ **Sign-in method** タブ → **匿名** を有効化。

ログイン画面は出ません。アプリが裏で身分証を取得するだけで、利用者側の操作は発生しません。

> **「匿名アカウントの自動クリーンアップ」はオンにしないでください。**
> 30日で匿名アカウントが消える設定です。有効にすると ★評価や「誰が追加したか」の紐付けが切れます。

### 4. セキュリティルールを貼る

**Firestore > ルール** タブの中身を、このリポジトリの [`firestore.rules`](firestore.rules) の内容に**まるごと置き換えて**「公開」します。

このルールは次の3点を担保しており、Firestore エミュレータ上のテストで実際に確認済みです。

| 守っていること | 仕組み |
|---|---|
| 共有IDを知らない人はデータに触れない | 部屋の中身は `lists/{共有ID}/...` の配下だけに置いている |
| 共有IDを総当たりで探せない | `lists` コレクション自体の一覧取得と、部屋ドキュメントの読み取りを禁止 |
| 未認証のアクセスを弾く | すべての読み書きに匿名認証を必須化 |

> ⚠️ **`match /{document=**}` に書き換えないでください。**
> 再帰ワイルドカードは「0個以上」のセグメントに一致するため親ドキュメントにも掛かり、
> 部屋ドキュメントの deny を打ち消してしまいます（これが原因で列挙できてしまう状態を実際に検出しました）。
> そのため `firestore.rules` は扱うパスをすべて明示的に列挙しています。

> ⚠️ **コレクショングループのインデックスは作らないでください。**
> Firestore が提案してくることがありますが、作ると全部屋を横断検索できる余地が生まれます。

### 5. 接続設定（設定済み）

[`js/firebase-config.js`](js/firebase-config.js) には設定値が記入済みです。**通常この手順は不要です。**

プロジェクトを作り直した場合のみ、**プロジェクトの設定 > マイアプリ** で `</>`（ウェブ）アプリを登録し（Firebase Hosting のチェックは不要）、表示された設定値でこのファイルを置き換えてください。

この値は Firebase の設計上**秘密情報ではなく**、公開リポジトリに含めて問題ありません。安全性は手順4のルールが担保しています。

### 6. 公開する

1. GitHub でリポジトリを **public** にする（private のままだと Pages は有料プランが必要です）
2. **Settings > Pages** で Source を `main` / `/ (root)` に設定
3. 発行された URL をスマホで開く

### 7. API キーに参照元制限をかける

[Google Cloud コンソールの認証情報](https://console.cloud.google.com/apis/credentials) でプロジェクトを選び、
`Browser key (auto created by Firebase)` →「アプリケーションの制限」→ **ウェブサイト** に次を追加します。

```
https://kakawo18.github.io/*
http://localhost:8000/*
```

これで、あなたのページ以外から読み込まれたキーは弾かれます。

> **なぜ必要か。** `js/firebase-config.js` はブラウザに配信されるため、アプリを開いた人は誰でも中身を読めます。
> リポジトリを private にしても隠せません（Firebase の API キーはアクセスを許可するものではなく
> プロジェクトを識別するだけなので、これ自体は仕様どおりです）。
> ただしこのアプリは匿名認証を通れば書き込める設計のため、設定値を拾った第三者が
> 無関係な部屋を作って無料枠を消費させることは理論上できます。
> **あなたの部屋のデータは共有IDを知らないと読めず、Blaze にしていないので課金も発生しません**が、
> 参照元制限をかけておくと、いたずら目的の流用はほぼ防げます。

## 使い方

### 物件を追加する

右下の **＋** を押し、物件名と場所を入れて保存します。必須はこの2つだけで、あとは分かる範囲で構いません。

**URL からの自動入力**（任意・要セットアップ）：[`worker/`](worker/) の中継サーバーを立てると、
物件ページの URL を貼るだけで家賃・間取り・面積・最寄駅などが自動で埋まります。
読み取れないページはその場でテキスト貼り付けに切り替わります。手順は
[worker/README.md](worker/README.md) を参照してください。設定しなければ手入力のみで普通に使えます。
1件あたり3円前後で、使うモデルは中継サーバー側の設定だけで変えられます。

場所の指定は2通りあります。

- **住所を入力する**：候補が出てくるので選ぶとピンが立ちます
- **地図で位置を指定する**：地図を動かして中央の十字を合わせ、「この位置に決定」

> 日本の住所は番地まで当たらないことがあります。候補が出ないときは地図から置いてください。これは異常ではなく通常の流れです。

### 位置が「だいたい」のとき

物件サイトは番地を伏せていることが多く、「横浜市西区北幸2丁目」までしか書かれていないことがあります。
このとき自動入力は、**番地を勝手に補いません。**代わりに、その物件を次のように扱います。

- 地図には点ではなく、**破線の円**（このあたり、という範囲）で表示されます
- ピンの隅に **?** が付き、一覧には **「位置 要確認」** が出ます
- 一覧の上に **「位置 要確認 ◯件」** が出て、押すとその物件だけに絞れます

**そのまま保存でき、内見のルートを考えるにはこれで足りることも多いはずです。**
正確な位置が分かったら、次のどちらかで確定できます。

- 物件を開いて **「地図で位置を確定する」** → 地図を動かして合わせるだけ（編集画面を開く必要はありません）
- 登録・編集の画面で **「この位置で確定する」** → 出ている位置でよければそのまま確定

確定すると円と印が消え、残件表示も減ります。

> 番地まで書かれていた場合は、これまでどおり普通のピンが立ちます。
> なお「番地まで」と読み取られていても住所に番地の形（`2-1-5` や `1番5号`）が無ければ、
> 念のため未確定として扱います。確かめずに済ませてしまうより安全なためです。

### 誰かを招く（使わなくても構いません）

ひとりで使うなら何もしなくて大丈夫です。一緒に探す相手ができたら、
**⋮ メニュー > URLをコピー** で共有 URL を送ります。相手はそれを開いて表示名を入れるだけで参加完了で、
それまでに貯めたリストもそのまま見えます。

> この URL を知っている人はリストを編集できます。転送には注意してください。
> 一度渡した相手を後から締め出す仕組みはないため、漏れた場合は JSON で書き出し、
> 新しいリストを作って読み込み直してください。

### 見る・絞る

- 下から一覧を引き上げられます（ハンドルをタップまたはドラッグ）
- 地図のピンをタップすると、その物件の条件が下から出ます
- ⚙ から家賃の上限・間取り・★・ステータスで絞れます。**絞ると地図のピンも同時に減ります**
- 「候補外」にした物件は既定で地図から隠れます（絞り込みでいつでも戻せます）

### バックアップ

**⋮ メニュー > JSONで書き出し / 読み込み**。Firebase プロジェクトごと失う事故への保険になります。

---

### 画面が古いままのとき

更新したのに機能が出てこない、ボタンを押しても何も起きない、という場合は端末に古い版が
残っています。**⋮ メニュー > アプリの版 > 最新版に更新** を押すと取り直せます。
物件データは Firestore にあるので、この操作で失われるものはありません。

その画面自体が出ないほど古い場合は、一度プライベートブラウズで開いてください。
プライベートブラウズはキャッシュを使わないため、必ず最新版が読み込まれます。

## 注意点

- **地図タイルは通信が必要です。** 圏外では地図が灰色になりますが、物件データと一覧はキャッシュから見られます（一度表示したエリアの地図は残ります）
- **画像は URL 参照のみ**です。物件サイトの画像は直リンクを弾かれて表示できないことがあります（その場合は代替表示になります）
- 同じ物件を二人が同時に編集した場合は**後から保存したほうが残ります**。誰がいつ更新したかはカードに表示されます
- 住所検索は [Nominatim](https://nominatim.openstreetmap.org) を利用し、規約に従って1秒あたり1リクエストに制限しています
- 地図は [OpenStreetMap](https://www.openstreetmap.org/copyright) のタイルを使用しています

## 色の決まり

**色にはひとつずつ意味を持たせ、重ねていません。** 画面に手を入れるときはこの表に従ってください。

| 色 | 意味 | 使う場所 |
|---|---|---|
| 🔵 青 `--accent` | **操作できるもの** | ボタン、リンク、選択中であること |
| 🔴 赤 `--danger` | **取り消せない操作** | 削除 |
| 🟠 琥珀 `--unsure` | **データが足りないこと** | 位置が未確定（円・印・「位置 要確認」） |
| 🟣 紫 / 🌸 赤紫 / 🟢 緑 / ⚪ 灰 | **検討がどこまで進んだか** | 気になる／内見予定／内見済／候補外 |

検討ステータスの4色は [`js/model.js`](js/model.js) の `STATUSES` にあります。

紫と赤紫が隣り合っているのは、「気になる」と「内見予定」がどちらも検討中の段階だからです。
緑は終わり、灰は候補から外れたことを表します。

> **押せないものを青で塗らないでください。** 状態を表す色とボタンの色が同じだと、
> 押せそうに見えるものと、ただの表示との区別がつかなくなります。
> 以前は「気になる」が基調色と同じ青で、まさにこの状態でした。
>
> **要確認の琥珀を、ステータスに使わないでください。** 以前は「内見予定」が橙で、
> 琥珀の印を乗せると印が沈んで見えませんでした。
>
> 4色はいずれも**白抜き文字が読める濃さ**（コントラスト比 4.9 以上）に揃えてあります。
> 差し替えるときはこの水準を下回らないようにしてください。

## 開発・動作確認

ライブラリ（Leaflet / Firebase SDK）は `vendor/` に同梱済みで、CDN もビルドも不要です。

```bash
# アプリを配信する
npx http-server -p 8000 -c-1

# 別のターミナルで、本物の Firebase を使わずに動かす
npx firebase-tools emulators:start --only firestore,auth
```

エミュレータに向けるには `http://localhost:8000/index.html?emulator=1` を開きます。
このクエリが付いているときは Service Worker を登録しないので、古い資産を掴む心配もありません。

### 確認済みの動作

Firestore エミュレータと Playwright で、次を実際に通してあります。

- 二人の画面を同時に開き、片方の追加・★評価・コメントがもう片方に反映されること
- ピンのタップで条件が表示され、ステータスでピンの色が変わること
- 絞り込みが一覧と地図の両方に効くこと
- 圏外で追加した物件が、通信復帰後に自動で送信されること
- `firestore.rules` が部屋の列挙・未認証アクセス・横断検索を拒否すること
- JSON の書き出しと読み込みでデータが復元されること
- 住所が丁目までのときに範囲の円が出て、あとから位置を確定でき、確定すると印が消えること
- この項目を持たない既存の物件が「要確認」にならないこと
- 描画された画素の色を読み、ステータス・基調色・要確認の色相がどれも30度以上離れていること、
  4色とも白抜き文字のコントラスト比が 4.5 以上あること

なお、地図タイルと住所検索は外部サービスのため、この確認では代替に差し替えています。実通信の確認は公開後に端末で行ってください。

## 今後の計画

このアプリを、身内以外の誰でも使えるサービスとして公開する場合の検討をまとめています。

📄 [docs/public-service-plan.html](docs/public-service-plan.html)

現時点の要点だけ書き出すと、次のとおりです。

- いま使っている **OpenStreetMap の公式タイルと Nominatim は、いずれも公開サービスでの利用が認められていません**。それぞれ地理院タイルと Geolonia Community Geocoder に差し替えれば、**無料のまま商用可の構成にできる見込み**です（どちらも出典の明示が条件）
- 住所検索は町丁目までの精度になりますが、このアプリは元から地図で位置を詰める導線を持っているため、致命的にはなりません
- **URL からの自動読み取りは、サービスとして続けてよいかの判断が必要です。** すでに実装済みの「テキスト貼り付け」だけを残せば、こちらから物件サイトへ取りに行かなくなり、この論点自体が消えます
- 有料オプションは、**会員登録を導入しなくても実現できます。** 権利を人ではなくリスト（共有ID）に紐づけて売る形になります

上記は調査時点の情報にもとづく見込みです。採用の前に一次情報を確認してください。未確認の項目は計画の末尾に列挙しています。
